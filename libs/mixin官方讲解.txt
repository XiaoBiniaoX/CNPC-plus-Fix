概述

MixinBooter 使任何 Mixin 的构建和用于修改其它模组的 Mixin 都能在 1.8~1.12.2 版本中轻松生效。

当前 Mixin 版本为 UniMix 0.15.3 的 CleanroomMC 分叉，基于 LegacyModdingMC 的 0.8.7 分叉，与 UniMixins 基本相同；

当前 MixinExtras 版本是 0.5.0 。

变更日志

从 4.2 开始，模组的 API 发生改变，所有使用 Mixin 的模组都推荐使用 MixinBooter，甚至包括那些混入原版 / Forge / 运行库的类的模组，为了避免 Mixin 版本不匹配与尝试实现修改后的 Mixin 的模组发生崩溃（看看你 原版修复）；感谢 Embeddedt 推荐并帮忙引入了此修改；

从 5.0 开始，包括了 LlamaLad7 的 MixinExtras，更方便开发者使用；

从 8.0 开始，模组支持 1.8~1.12.2 的所有版本；

从 8.4 开始，模组试图与 SpongeForge 兼容（仅支持 1.12.2）；

从 9.2 开始，MixinLoader 注解被重新启用，以便在 1.8.X 使用（因为 1.8.X Forge 还未收集类实现接口的信息）；

从 10.0 开始，模组开始使用更新的 Mixin 0.8.7。

        transitive = false
    }
    annotationProcessor ('zone.rong:mixinbooter:10.7') {
        transitive = false
    }
     
    // RetroFuturaGradle:
    String mixinBooter = modUtils.enableMixins('zone.rong:mixinbooter:10.7')
    // modUtils.enableMixins('zone.rong:mixinbooter:10.7', 'mod_id.mixins.refmap.json') << add refmap name as 2nd arg (optional)
    api (mixinBooter) {
        transitive = false
    }
    annotationProcessor (mixinBooter) {
        transitive = false
    }
}
若需修改原版、Forge 或任何很早传递给 ClassLoader 的类（例如 Guava）；

请创建一个实现 IFMLLoadingPlugin 的 CoreMod，并让该类实现 IEarlyMixinLoader；

若需修改普通模组的类，请在模组任意位置创建一个普通类，实现 ILateMixinLoader；

@MixinLoader 注解从的功能与 LateMixinLoader 类似，两者可以同时使用，特别是当模组需要支持 1.8.X 时。

IEarlyMixinLoader 和 ILateMixinLoader 都要求返回一个包含 Mixin 配置文件名的 List<String>，文件名应指向 Mixin 配置文件的路径（相对于项目的 resources 根目录）。

实际上只需要实现MixinBooter的接口并且传递好信息就万事大吉了，比从coremod手动引导方便太多了

使用注意

模组一般情况下可以替代 MixinBootstrap 和 兼容 Mixin 0.7-0.8，若安装此模组则无需安装它们；

模组对加载顺序有较高的要求，不要删掉或覆盖模组名前面的“!”符号，以确保模组在 mods 文件夹中排在靠前位置，优先加载；

模组可能与以库形式安装的 LiteLoader （如部分启动器的一键安装选项）冲突导致启动失败，请尝试仅安装 Forge 并将单独下载的 LiteLoader 安装在 mods 文件夹，更多兼容信息请参考 LiteLoader 词条的模组兼容部分；

ESSENTIAL 可能与此模组冲突 （GitHub Issue），请升级 ESSENTIAL 版本至 1.3.2.6 以上；

在 10.0 及以上版本中，模组可能与部分使用 Mixin 的模组存在兼容性问题，且仅 10.6+ 兼容 1.8.X；

若更新后无法启动，暂时回退到 9.4 版本即可；

若使用 Cleanroom，则不需要此模组。对于开发者，推荐转向更新的 Mixin 实现，在 此模板 中有介绍。
